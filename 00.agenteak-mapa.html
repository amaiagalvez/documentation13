instalazioa
  • npm i -g @fission-ai/openspec@1.14.1
  • openspec config set delivery skills
  • rm -rf .claude/agents .claude/skills .opencode/agents .opencode/skills
egitura
  • openspec/config.yaml — proiektuaren testuingurua eta arauak (skill-ek irakurtzen dute)
  • openspec/specs/<capability>/spec.md — egungo egia; ez editatu eskuz
    • basics-* — auth, crud-base, trash-archived, roles, settings, email, navigation…
    • *-domain — entities, projects, locations
    • entity-projects-bridge, package-boundaries, epics-comments, planning-timeline, calendars, excel-export, files13
  • openspec/changes/<id>/ — aldaketa bat = PR bat
    • proposal.md — zergatik eta zer aldatzen den
    • design.md — erabaki teknikoak (behar denean)
    • tasks.md — zereginen zerrenda - [ ] / - [x]
    • specs/<capability>/spec.md — deltak: ADDED · MODIFIED · REMOVED · RENAMED
  • openspec/changes/archive/ — amaitutako aldaketak, datarekin
nola erabili (fluxua)
  • 1. Esploratu — openspec list, list --specs, show <capability> --type spec · skill openspec-explore
  • 2. Erabaki — proposal behar da? Spec-a berrezartzen duen bug-a, typo-a edo config-a → zuzenean konpondu
  • 3. Sortu — openspec-propose: proposal + design + specs + tasks
  • 4. Balidatu — openspec validate <id> --strict berde egon arte
  • 5. Onarpena — hemen gelditu; ez inplementatu onartu arte (aldaketak: openspec-update-change)
  • 6. Inplementatu — openspec-apply-change: tasks.md ordenan, - [x] markatuz
  • 7. Artxibatu — merge ondoren openspec-archive-change (archive <id> --yes): deltak specs/-era. Artxibatu gabe sinkronizatzeko: openspec-sync-specs
komandoak

list · list --specs · show · validate --all --strict · archive · view (dashboard) · update (skill-ak birsortu CLI-a eguneratu ondoren). CLI ofiziala: @fission-ai/openspec@1.14.1.
